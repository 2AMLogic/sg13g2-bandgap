# Record 20261001-043806-729d889

- **Experiment**: closed-loop-vref-boxtc-trim (issue #229)
- **Claim**: the post-trim box-method TC re-measurement DR-0011's
  +/-0.5% trimmed budget obligates, bounding the trim-induced TC
  degradation. A correctly-trimmed die sits at its OWN TC-null
  (the mismatch population's errors are PTAT-shaped; correcting
  the level with R1 restores the null ratio -- see
  design/bandgap_trim_network.md Sec 3), so the residual
  trim-induced TC comes from the sub-code mis-aim (+/-1/2 LSB
  quantization + <~0.4 LSB chord-fit aim), i.e. <=~1 code off
  null. This bench measures the box-method TC
  ((vmax-vmin)/(vref(27C)*165 C)) on the same 8-temperature grid
  as sim/closed-loop-vref-pvt-boxtc at codes {127, 128, 129} (the
  +/-1-code band, full corner x supply grid) and gates the
  +/-1-code delta vs the code-128 baseline at 17.86 ppm/C (the
  ~0.175% headroom DR-0011's budget carries, over the 98 C span
  from the 27 C trim point). Codes {0, 64, 192, 255} on
  {typ, bcs, wcs}/3.30 V bound the TC-vs-code sensitivity slope
  and its saturation (reported, ungated). NOT a claim against a
  different target -- the ratified TC row (< 50 ppm/C) is
  unchanged.
- **Method**: the grid runs as .nodeset-seeded .op points (the
  sim/closed-loop-vref-mc technique -- see the experiment README);
  the transient fixture (200us ramp, 3ms hold, the #222
  settledness convention) is validated per process corner at
  code 128/27C/3.30V and must agree with the .op to
  <= 0.0001 V -- see the *_tranval_* rows in the parsed CSV.
