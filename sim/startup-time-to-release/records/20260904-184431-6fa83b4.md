# Record 20260904-184431-6fa83b4

- **Experiment**: startup-time-to-release
- **Claim**: the same co-simulated bandgap_core + bandgap_amp +
  bandgap_startup closed-loop assembly sim/closed-loop-startup
  proves self-starts and settles (design/bandgap_top.sch's own
  wiring), but sampled at a fixed-time checkpoint ladder
  (100 200 300 400 500 600 700 800 900 1000 2000 us) instead of one early + one final
  checkpoint, so the earliest time at which the full closed-loop
  release criteria (startup released: v(det) <= 0.2*vdd
  and |i(XMKFB)| <= 50e-9 A; loop closed:
  |sns1-sns2| <= 0.020 V; not railed: fb within
  [0.05 V, vdd-0.05 V]) hold AND keep
  holding through the end of the simulated window (2 ms) can be
  read off directly, across the full temperature x supply x
  HBT/MOS/resistor-process-corner PVT grid. Filed as a direct
  follow-up to PR #128's EE-key review, which found no committed
  testbench in this tree reports an explicit time-to-release figure
  to compare against the draft "Startup: self-starting, < 1 ms"
  spec row (spec/porting-plan.md, still unratified -- #125). This
  record is that missing measurement; it is evidence for a spec row
  comparison, not a conformance claim against a ratified spec (none
  exists yet).
- **Why fixed-time checkpoints, not a WHEN/crossing search**: tried
  first and rejected -- at several PVT corners, most visibly the
  design's own typ/27C/3.30V nominal point, det and i(XMKFB) never
  rise above the release threshold at all during the vdd ramp (peak
  det ~0.48 V against a 0.66 V threshold at that corner; peak
  i(XMKFB) ~4.3 nA against the 50 nA threshold), so a
  `meas tran ... WHEN v(det)=<thresh> FALL=1` finds no crossing and
  fails with "out of interval" -- confirmed by direct test, not
  assumed. AT= sampling on a fixed ladder has no such failure mode
  and is what this template uses instead (see its own header).
- **Resolution**: 100 us below 1 ms (this experiment's own claim
  window), so a reported `release_time_us` is accurate to within
  one ladder step, not an exact crossing instant. `release_time_us`
  is defined as the earliest ladder point at which the release
  criteria hold AND continue to hold at every later ladder point
  through 2000u (a suffix-of-PASS rule) -- a corner that transiently
  looks released then regresses is not misreported as released
  early. `NOT_RELEASED` means the criteria never reach that stable
  suffix within the 2 ms simulated window.
